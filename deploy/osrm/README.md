# OSRM: свой маршрутизатор для Loginex

Пока OSRM не поднят, километры считаются как «прямая × коэффициент региона».
Проверка на реальных участках показала, что на европейской части ошибка в
среднем 2 % — и это везение, а не гарантия (на подъездах к базе разброс был
до 30 %: 13 км оценки против 18,7 км дороги). Для денег нужен измеренный
километр, а не правдоподобный.

Этот каталог — готовый набор, чтобы поднять **свой** OSRM (решение от 1
ноября: не публичный демо-сервер, а своя машина: у нас тысячи запросов и
требование к предсказуемости).

---

## 1. Сервер

| Параметр | Минимум | Комфортно |
|---|---|---|
| CPU | 4 ядра | 8 ядер |
| RAM | 8 ГБ | 16 ГБ |
| Диск | 60 ГБ SSD | 100 ГБ SSD |
| ОС | Ubuntu 22.04 / Debian 12 | то же |

Размер данных: `russia-latest.osm.pbf` — около 3,5 ГБ; после подготовки
(`.osrm.*` файлы) занимает ~12–15 ГБ. Подготовка на 8 ядрах — порядка 40–70
минут, повторная настройка (`osrm-customize`, без пересборки графа) — минуты.

Для тестов вместо всей России можно взять федеральный округ (ЦФО ~600 МБ):
подготовка занимает 5–10 минут, и этого достаточно, чтобы проверить расчёт на
участках Москвы, Ярославля, Тулы.

---

## 2. Подготовка данных (один раз)

```bash
cd /opt/loginex-osrm
# 1. Скачать карту (или округ для теста)
./prepare.sh russia            # ~3,5 ГБ, ждёт 40–70 минут
# ./prepare.sh central-federal-district   # быстрый вариант для проверки

# 2. Поднять сервис
docker compose up -d osrm
curl "http://127.0.0.1:5000/route/v1/driving/37.7376,55.4207;37.6182,54.1961?overview=false"
```

Если в ответе есть `"code":"Ok"` и `"distance"` — сервис жив.

Обновление карты раз в месяц:

```bash
./prepare.sh russia --refresh   # скачивает свежий .pbf и пересобирает
docker compose restart osrm
```

## 3. Подключение к приложению

В переменных окружения приложения (Vercel → Settings → Environment Variables,
или `.env` для локального запуска):

```
OSRM_URL=http://<адрес-сервера>:5000
```

Больше ничего менять не нужно: `lib/routing/service.ts` читает `OSRM_URL` и
передаёт его в движок расстояний. Если переменной нет или сервис не отвечает —
расчёт продолжается на оценке, а в плане честно появляется пометка
`достоверность: estimated`.

Проверка на данных своей организации:

```bash
OSRM_URL=http://<адрес>:5000 npm run routing:osrm -- <organizationId>
```

Скрипт печатает: сколько пар считалось, сколько ушло запросов и времени,
расхождение оценки с дорогой на каждом участке, эмпирический коэффициент
«дорога / прямая» для региона базы. Эту цифру и надо ставить в настройки
региона, если она отличается от 1,2.

---

## 4. Как считается время

Километры берутся из OSRM (это дорога), **время — из модели региона**
(55 км/ч с грузом, 60 порожним, настраивается).

Причина: OSRM считает по легковому профилю, где трасса проходится за
90–110 км/ч. Фура с грузом так не едет, плюс режим труда и погрузки. Если
подставить легковое время, календарь рейса окажется на четверть короче
реальности — и логист пообещает клиенту срок, который машина не выдержит.
Время OSRM сохраняется в участке как `osrmHours` — для сверки, не для расчёта.

---

## 5. Чего в этой поставке нет (и почему)

* **Платные дороги.** OSRM их не считает. В экономике статья «платные дороги»
  есть, но заполняется только если участок размечен вручную; иначе она
  помечена как неизвестная, а не нулевая.
* **Грузовой профиль.** `car.lua` — единственный поддерживаемый профиль
  без пересборки графа под классы ТС. Для весовых ограничений нужен
  отдельный профиль, это следующий шаг, когда появятся данные о разрешённых
  маршрутах для тяжёлых машин.
* **Пробки.** Статичный граф без учёта часа пик; компенсируется моделью
  скорости региона, а не догадками внутри маршрутизатора.
