# Тарифы и умный диспетчер

## Тарифы

Источник правды по планам, ценам и лимитам — `lib/billing/plans.ts`.
План хранится в `OrganizationSettings.plan` (`trial | free | start | park | company`).

| План         | Цена, ₽/мес | Лимит машин |
| ------------ | ----------- | ----------- |
| Пробный      | 0           | без лимита  |
| Бесплатный   | 0           | 2           |
| Старт        | 3 500       | 3           |
| Парк         | 12 000      | 15          |
| Компания     | 35 000      | 50          |

**Пробный период — 14 дней** от создания организации, действует как «Компания».
Когда он истекает, а платный план не выбран, автоматически действует
«Бесплатный» (2 машины). Срок считает `resolvePlan()` по дате создания
организации — чистая функция, покрыта тестами.

**Проверка лимита** — в `POST /api/vehicles`: при превышении возвращается
409 с `code: "plan_limit"`, названием плана и лимитом. Страница `/pricing`
показывает текущий план, остаток пробного периода, занятость лимита
(`машин в парке / лимит`) и кнопки выбора плана (только администратор).

**Оплата пока вручную:** администратор выбирает план в `/pricing`, оплата
проводится вне приложения (эквайринг и автопродление — следующий этап).
Поле тарифа уже заложено в `OrganizationSettings.plan`.

## Умный диспетчер

На странице «Виртуальный логист» (`/planner`) — блок «Умный диспетчер»:
запрос словами превращается в фильтры и набор грузов с ожидаемой прибылью.

Пример запроса:

```
Найди завтра из Ярославля тент 20 т, от 65 000 ₽ и не меньше 45 ₽/км
```

Разбор — `lib/dispatcher/query.ts` (чистая функция, покрыта тестами):

- **даты:** сегодня / завтра / послезавтра, «12.10», «12 октября»
  (дата без года, ушедшая далеко назад, считается будущей — следующий год);
- **города:** после «из» и «в» с заглавной буквы (чтобы «в рейс» не стало
  городом); сравнение по основе первых 4 символов — «Ярославля» ≈ «Ярославль»;
- **вес:** «от N т» — минимум, «до N т» — максимум, голое «N т» — максимум
  (диспетчер ищет груз под машину на N тонн);
- **цена:** «от N» (N ≥ 500, без единиц) или «N ₽»;
- **ставка:** «N ₽/км» — забирается раньше цены, чтобы не спутаться;
- **кузов:** тент, рефрижератор, изотерм, бортовой, фургон, площадка,
  цистерна, самосвал, лесовоз, зерновоз, трал, автовоз, контейнеровоз.

**Подбор** — `GET /api/dispatcher/search?q=…&vehicleId=…` (данные строго
в границах организации): берёт доступные грузы накопленной базы
(`AtiCache`, статусы `expired/archived/taken/converted` отсекаются),
применяет фильтры и считает по каждому:

- ₽/км = цена / расстояние;
- оценка топлива = расстояние × расход машины × коэффициент загрузки ×
  **цена литра из последних топливных чеков** (`fuelPriceRubPerL`);
  нет чеков с литрами — прибыль не выдумывается, остаются цена и ₽/км;
- ожидаемая прибыль = цена − оценка топлива, и маржа в %.

Сортировка — по ожидаемой прибыли. Если выбрана машина, грузы тяжелее её
грузоподъёмности отсекаются сразу, а расход считается под её загрузку.

**Взять в работу** — существующий поток `POST /api/orders/from-cache`:
груз становится заказом, планировщик пересобирается сразу.
