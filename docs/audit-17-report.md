# Аудит программы — отчёт 17-го промпта

Дата: 2026-10-19. Метод: обход 86 GET API под живой сессией, браузерная приёмка
экранов (playwright + chromium), изолированный эксперимент по геолокации
(тест-водитель создан и удалён), чтение кода. Тесты: 390 unit / 600 vitest /
384 isolation — все зелёные (проверено ранее). **500-х ошибок в API нет.**

Скриншоты: `docs/audit-screens/taskI-*.png`.

## A. Подтверждённые проблемы (с доказательством)

### A1. Геолокация с телефона «не распознана» — причина найдена и доказана
**Что доказано экспериментом** (изолированный тест-водитель, уборка выполнена):

| Сценарий | POST /api/m/location | Результат |
|---|---|---|
| Смена активна + незакрытый рейс | 2 POST, оба 200 | координаты записаны в БД |
| Смена закрыта | **0 постов** | GPS молча выключен |
| Смена активна, заказ закрыт | **0 постов** | GPS молча выключен |

**Причина (код):** `app/m/page.tsx:309` — координаты шлются только при
`shift && driver.id && hasActiveTrip`. `hasActiveTrip` = есть незакрытый заказ.
Плюс `app/m/page.tsx:805` — индикатор GPS показан только при
`hasActiveTrip && shift`, т.е. водитель **не видит вообще никакого статуса GPS**,
когда смены/рейса нет — отсюда ощущение «геолокация не распознана».
Отказ в доступе показывается тостом один раз и тот же тост привязан к флагу —
после первого показа не повторяется.

**Что нужно:** (1) показывать плашку GPS всегда с причиной («Смена не начата» /
«Рейс не назначен» / «Нет доступа к геолокации»); (2) повторять подсказку об
отказе в доступе; (3) по запросу логиста — режим «дежурной передачи координат»
для машин в парке (необязательно, обсуждаемо).

### A2. Учёт ремонта авто: данные в БД есть, пути в интерфейс нет
- Модели **есть**: `MaintenanceLog` (cost, mileage, serviceName, status),
  `RouteExpense` (type=repair, vendor, amount, odometer, photoId).
- API создания: только мобильный `POST /api/m/maintenance` и расходы рейса
  (`/api/routes/[id]/expenses`, `/api/m/expenses`). **`/api/maintenance` — только GET.**
- UI: `/maintenance` — **нет ни одной кнопки и ни одного поля ввода** (пустой
  экран); `/lm/fleet` — вкладки «Машины» / «ТО и страховка», слова «ремонт» нет.
- **Поля «заказ-наряд» / номер документа ремонта нет ни в одной модели.**
- **Нет сводки «сколько денег ушло на ремонты по парку».**

**Итог:** потратиться на ремонт с заказ-нарядами система учесть не позволяет.

### A3. Документы: механизм работает, но вход в него потерян; email нет
- **Доказано работающим:** API `/api/routes/[id]/documents` для рейса с 2 заказами
  вернул `ttn, ttn, waybill, contract, contract`; печать `/print/route/[id]`
  отрендерила все 5 листов (ТТН, путевой, договор). Тайлы и бланк корректны.
- **Проблема 1:** кнопка «Документы» есть только в классическом UI `/routes`
  (ActiveRouteCard → RouteDocumentsDialog). В новой карточке рейса
  `/lm/routes/[id]` — **нет кнопки документов и печати** (см. скриншот). Логист
  в новом интерфейсе документы не найдёт — отсюда «накладных нет».
- **Проблема 2:** рейсы организации в демо-данных созданы **без заказов** → API
  отдаёт только путевой лист; ТТН/договор появляются лишь при наличии заказов
  в рейсе. Внешне = «накладных нету».
- **Проблема 3:** отправки документов на email **нет вообще** — `lib/mailer.ts`
  подключён только к восстановлению пароля; в диалоге документов email-поля нет.
- SMTP в `.env` не настроен (и на проде, вероятно, тоже).

### A4. Отчёты для бухгалтера: API есть, кнопок в новом UI нет
- `/api/reports/export` (txt|csv) — 200. `/api/payments/export` (CSV, BOM, `;`) — 200.
- `/lm/reports`: слов «Экспорт / Скачать / CSV / Excel / бухгалтер» — **0
  вхождений**, единственная кнопка «Обновить». В классическом `/reports` —
  «Выгрузка» ×1.
- Готовых бухгалтерских форм (например, сверка оплат по месяцам с НДС/без) в UI нет.

### A5. Песочница логиста: перетаскивания нет — жалоба подтверждена
- На `/orders`: элементов `[draggable=true]` — **0**, курсоров grab/move — **0**,
  drag&drop-библиотек нет.
- Режимы: «Выбор | Связь | Группа | Маршрут», листы 1–3. Связи и состав
  маршрута — только кликами по карточкам.
- Подтверждённый дискомфорт пользователя: «неудобно перетаскивать и соединять линиями».

### A6. Мелочи и риски
- `/lm/analytics`, `/lm/warehouse`, `/lm/finance` отдают 404 — в навигации их нет,
  битых ссылок в меню не найдено (проверены все href). Не проблема, но если
  планировались — не реализованы.
- `503 /api/ati/cron` — CRON_SECRET не задан; ATI как платный сервис не подключаем
  (соглашение). Ожидаемо.
- В карточке рейса `/lm/routes/[id]` расходы рейса отображаются («Деньги рейса»),
  но кнопки добавления расхода на скриншоте не видно — требует уточнения при
  исправлениях.
- В `/routes` кнопка «Документы» продублирована 10 раз на странице (по карточке
  рейса) — визуальный шум, но не слом.

  серая плитка ушла (правки 16-го промпта действуют).
- Документы API + печать (ТТН/путевой/договор) — см. A3.
- Экспорт отчётов API — см. A4.
- Все основные экраны `/lm/*`, `/routes`, `/orders`, `/dashboard` — 200, ошибок
  консоли нет.
- GPS-контур: API `/api/m/location` корректен (requireDriver, org-scoped) —
  проблема только в условиях включения на клиенте.
- API-обход: 86 GET → 200×55, 400×3 (ожидаемо), 403×13 (owner/driver-only),
  404×14 (несуществующие id — норма), 503×1 (ATI cron), **500×0**.

## C. Предлагаемый план исправлений (по приоритету, жду команду)

| № | Задача | Оценка |
|---|---|---|
| 1 | GPS: плашка всегда + причина («смена не начата» / «рейс не назначен» / «нет доступа») | 1–2 ч |
| 2 | Документы в новой карточке рейса: кнопка «Документы/Печать» + выбор видов | 1–2 ч |
| 3 | Отчёты: кнопки «Экспорт CSV/бухгалтерский» в `/lm/reports` (API уже есть) | 1–2 ч |
| 4 | Ремонты: экран учёта (сумма, заказ-наряд, пробег, фото) + сводка по парку; поля «номер заказ-наряда» в схему + миграция | 3–5 ч |
| 5 | Песочница: настоящее перетаскивание карточек (drag & drop) + связи линиями | 4–8 ч |
| 6 | Почта: отправка документов клиенту/бухгалтерии (SMTP — нужен бесплатный провайдер, спрашивать) | 2–3 ч + настройка |
| 7 | Мелкое: дубль «Документы» в `/routes`, дорезка `/maintenance` | 1 ч |

Порядок можно менять. Пункты 1–3 быстрые и снимают главные жалобы; 5 — самая
большая работа; 6 требует выбора почтового провайдера (платить не хотим —
спрашивать перед подключением).
