# Почему мы обращаемся к общей бирже ATI.SU и как именно получаем грузы

Документ для переговоров с ATI.SU. Здесь — только то, что делает программа,
без приукрашивания: если ATI сочтёт способ неприемлемым, мы готовы перейти
на официальный эндпоинт или лицензионный тариф.

---

## 1. Кто мы и что делаем

Мы делаем программу для логистов и диспетчеров грузоперевозок. Программа
**многопользовательская**: организация регистрируется, подключает свой
аккаунт ATI.SU, вносит свой автопарк (машины, водители, свою базу) и ведёт в
ней свою работу. Данные у организаций не пересекаются: у каждой свои
машины, свои водители, свои настройки и свой накопленный список грузов.

Мы сами **не перевозчик и своего автопарка не имеем**. Для нас ATI.SU —
источник данных, из которых программа строит маршрут для того, кто ей
пользуется.

Задача программы: найти грузы, собрать из них маршрут из нескольких плеч
(с обратной загрузкой и возвратом на базу) и посчитать, выгоден ли рейс.
Ручной подбор на сайте при этом не отменяется — программа должна делать то
же самое, но быстрее и с расчётом.

## 2. Почему официального API не хватает

Через официально описанный API организация получает только три набора
данных:

| Эндпоинт | Что возвращает |
|---|---|
| `GET /webapi/v1.0/loads/byboards` | грузы площадок, где организация участник |
| `GET /webapi/v1.0/loads` | собственные грузы организации |
| `POST /webapi/v1.2/orders/search` | собственные заказы организации |

Общего поиска по бирже среди описанных эндпоинтов нет. Что это значит на
практике — на тестовом подключении аккаунта перевозчика:

- площадки, где он участник: **2 шт.**, грузов на них — **114**, и ни один
  не подходит его региону и его машинам;
- официальный поиск по его городу (Ярославль) возвращает **0 грузов**;
- на сайте ati.su в том же городе в радиусе 300 км — **около 2 950 грузов**.

Разница не в настройках фильтра. Площадки ATI — это закрытые клубы:
грузовладелец добавляет к себе конкретного перевозчика, и компанию с
небольшим рейтингом на многие площадки не принимают. В итоге аккаунт,
который заходит на ati.su и видит тысячи грузов, через API получает ноль.

Следствие для программы: используя только описанный API, она физически не
может показать диспетчеру грузы, которые он видит на сайте в два клика.
Программа получается не заменой сайта, а его худшей копией — и диспетчер
продолжает искать на ati.su руками, а маршрут считать на бумаге.

## 3. Как именно мы получаем грузы

**Источник.** Мы обращаемся к тому же поиску, который использует страница
поиска грузов на loads.ati.su:

```
POST https://loads.ati.su/webapi/v1.0/loads/search
Authorization: Bearer <токен организации>
Cookie: sid=<токен организации>
```

**Чей токен.** Всегда токен **той организации, которая работает в программе
сейчас**. Каждая организация подключает ATI сама (OAuth или вводом токена в
своих настройках), и каждый наш запрос уходит в её аккаунт, считает её
лимиты и виден в её подключениях. Мы не используем один общий служебный
аккаунт и не запрашиваем ничего от имени других организаций.

**Что отправляем.** Фильтр по городу и радиусу, постранично:

```json
{
  "exclude_geo_dicts": true,
  "page": 1,
  "items_per_page": 50,
  "filter": {
    "sorting_type": 2,
    "from": { "id": 88, "type": 1, "radius": 300, "exact_only": false }
  }
}
```

Запрос уходит **по нажатию кнопки диспетчером** («Собрать регион» или
«Искать»), а не по расписанию и не continuously. Одно нажатие — до 25
страниц.

**Что забираем из ответа.** Только сведения о грузе:

- откуда и куда: название города, область, координаты точки погрузки и выгрузки;
- расстояние по маршруту;
- вес, объём, тип груза;
- тип кузова и тип погрузки;
- ставка (с НДС / без НДС);
- даты загрузки;
- **название** фирмы-фрахтователя и её идентификатор.

**Чего мы не забираем.** Телефоны, e-mail, имена контактных лиц — никогда
автоматически. Из ответа биржи мы не читаем и не сохраняем ничего, кроме
перечисленного выше; это зафиксировано тестом в нашем коде, который падает,
если кто-то добавит контактные поля снова.

Телефон фрахтователя диспетчер получает **только** своим действием —
нажатием кнопки «Узнать телефон». Это отдельный осознанный запрос, а не
побочный эффект поиска или отправки маршрута. Мы понимаем, за что ATI
делает замечания, и автоматический сбор контактов убран.

## 4. Нагрузка на систему

- Один поиск = **1 запрос**.
- Полный обход региона вокруг базы организации (радиус 300 км, ~2 950
  грузов) ≈ **230 запросов**, потому что биржа отдаёт примерно 12–13 грузов
  на страницу независимо от запрошенного `items_per_page`. Это ограничение
  тарифа, а не наш выбор: запрашивать больше страница не отдаёт.
- Темп: **не более 8 запросов в секунду** (описанный лимит ATI — 10 rps),
  между страницами пауза, на `HTTP 429` — остановка и повтор, а не
  увеличение темпа. Параллельных «утяжеляющих» запросов мы не делаем.
- Полный проход по региону занимает несколько минут и происходит по
  нажатию кнопки, а не в фоне круглосуточно.

## 5. Что мы проем у ATI

1. **Допустим ли такой способ** получения грузов с точки зрения ATI — мы
   используем тот же поиск, что и сайт, с токеном самой организации.
2. Если нет — **подскажите правильный путь**: мы готовы перейти на
   официально описанный эндпоинт общего поиска, если он существует и нам
   откроют доступ, или на лицензионный тариф API.
3. Если общего поиска в API нет в принципе — как перевозчику работать с
   биржей через API, не заходя на сайт? Без этого автоматизация подбора
   груза невозможна, а мы делаем программу именно для этого.
4. Нас устраивает явный лимит запросов и любая пауза, которую ATI сочтёт
   нужной, — мы подстроимся.

---

**Коротко, одной фразой:** описанный API отдаёт организации только грузы её
площадок, и по её региону это часто ноль грузов; поэтому программа берёт
грузы тем же поиском, которым их отдаёт сайт ati.su, с токеном самой
организации, в пределах описанного лимита, по нажатию кнопки диспетчера, и
без автоматического сбора контактных данных.
