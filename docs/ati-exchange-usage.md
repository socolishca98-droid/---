# Почему мы обращаемся к общей бирже ATI.SU и как именно получаем грузы

Документ для переговоров с ATI.SU. Здесь — только то, что делает программа,
без приукрашивания: если ATI сочтёт способ неприемлемым, мы готовы перейти
на официальный эндпоинт или лицензионный тариф.

---

## 1. Кто мы и что делаем

Мы перевозчик (свой автопарк, свои машины и водители) и делаем программу
для своего диспетчера: она ищет грузы на ATI, собирает из них маршрут
(несколько плеч с обратной загрузкой) и считает, выгоден ли рейс.

Программа работает **от имени нашей организации и с её токеном**. Своего
парка грузов у нас нет — мы подбиратель, поэтому доступ к бирже грузов для
нас не удобство, а условие работы.

## 2. Почему официального API не хватает

Через официально описанный API мы получаем только три набора данных:

| Эндпоинт | Что возвращает |
|---|---|
| `GET /webapi/v1.0/loads/byboards` | грузы площадок, где наша организация участник |
| `GET /webapi/v1.0/loads` | наши собственные грузы |
| `POST /webapi/v1.2/orders/search` | наши собственные заказы |

Общего поиска по бирже среди описанных эндпоинтов нет. Для нашей
организации это даёт:

- площадки, где мы участник: **2 шт.**, грузов на них — **114**, и ни один
  не подходит нашему региону и нашим машинам;
- в результате официальный поиск по нашему городу (Ярославль) возвращает
  **0 грузов**.

При этом на сайте ati.su любой пользователь видит в этом же городе **около
2 950 грузов** в радиусе 300 км. Разница не в настройках фильтра: площадки
просто не содержат этих грузов, а площадки — закрытые клубы, и малого
перевозчика с небольшим рейтингом на многие из них не принимают.

То есть программа, использующая только описанный API, физически не может
показать диспетчеру те грузы, которые он видит на сайте в двух кликах.
Диспетчеру приходится искать на ati.su вручную, перезванивать и строить
маршрут на бумаге — то есть программа не заменяет сайт, а дублирует его
худшей версией.

## 3. Как именно мы получаем грузы

**Источник.** Мы обращаемся к тому же поиску, который использует сама
страница поиска грузов на loads.ati.su:

```
POST https://loads.ati.su/webapi/v1.0/loads/search
Authorization: Bearer <токен нашей организации>
Cookie: sid=<токен нашей организации>
```

**Что отправляем.** Фильтр по городу и радиусу, постранично:

```json
{
  "exclude_geo_dicts": true,
  "page": 1,
  "items_per_page": 50,
  "filter": {
    "sorting_type": 2,
    "from": { "id": 88, "type": 1, "radius": 300, "exact_only": false }
  }
}
```

Запрос уходит по нажатию кнопки диспетчером («Собрать регион») — не по
расписанию и не continuously. Одно нажатие — до 25 страниц.

**Что забираем из ответа.** Только сведения о грузе:

- откуда и куда: название города, область, координаты точки погрузки и выгрузки;
- расстояние по маршруту;
- вес, объём, тип груза;
- тип кузова и тип погрузки;
- ставка (с НДС / без НДС);
- даты загрузки;
- **название** фирмы-фрахтователя (и её идентификатор).

**Чего мы не забираем.** Телефоны, e-mail, имена контактных лиц — никогда
автоматически. Из ответа биржи мы не читаем и не сохраняем ничего, кроме
перечисленного выше; контактные поля в ответе биржи мы просто не
обрабатываем (это зафиксировано тестом в нашем коде, который падает, если
кто-то добавит их снова).

Телефон фрахтователя диспетчер получает **только** своим действием —
нажатием кнопки «Узнать телефон», и этот запрос виден как отдельное
осознанное действие. Мы понимаем, за что ATI делает замечания, и этот
момент убран.

## 4. Нагрузка на систему

- Один поиск = **1 запрос**.
- Полный обход региона вокруг нашей базы (радиус 300 км, ~2 950 грузов) =
  около **230 запросов**, потому что биржа отдаёт примерно 12–13 грузов на
  страницу независимо от запрошенного `items_per_page`. Это ограничение
  тарифа, а не наш выбор: запрашивать больше страница не отдаёт.
- Темп: **не более 8 запросов в секунду** (описанный лимит ATI — 10 rps),
  между страницами пауза, на `HTTP 429` — остановка и повтор, а не
  увеличение темпа. Параллельных «утяжеляющих» запросов мы не делаем.
- Полный проход по региону занимает несколько минут и происходит по
  нажатию кнопки, а не в фоне круглосуточно.

## 5. Что мы проем у ATI

1. **Допустим ли такой способ** получения грузов с точки зрения ATI — мы
   используем тот же поиск, что и сайт, с токеном нашей организации.
2. Если нет — **подскажите правильный путь**: готовы перейти на
   официально описанный эндпоинт общего поиска, если он есть и нам откроют
   доступ, или на лицензионный тариф API.
3. Если общего поиска в API нет в принципе — как перевозчику работать с
   биржей через API, не заходя на сайт? Для нас это не «удобство», а
   единственный способ автоматизировать подбор груза.
4. Нас устраивает явный лимит запросов и любая пауза, которую ATI сочтёт
   нужной, — мы подстроимся.

---

**Коротко, одной фразой:** официальный API отдаёт нам только площадки, где
мы участник, и по нашему региону — ноль грузов; поэтому мы берём грузы тем
же поиском, которым их отдаёт сайт ati.su, с нашим токеном, в пределах
описанного лимита, по нажатию кнопки диспетчера, и без автоматического
сбора контактных данных.
